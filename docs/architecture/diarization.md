# Diarization

Diarizer modes, dual-track merging, speaker matching and tuning.

**Diarization:**
- `FluidDiarizer` uses FluidAudio (CoreML/ANE) for on-device speaker diarization — no HuggingFace token needed. Three modes: `.offline` (default), `.sortformer` (overlap-aware, up to 4 speakers, via `SortformerDiarizer`) and `.nemotron` (NVIDIA Nemotron 3, overlap-aware, up to 8 speakers, via `Nemotron3Diarizer`). Selected via `AppSettings.diarizerMode`; `DiarizerMode.speakerCap` bounds the speaker-count steppers. Both overlap-aware modes ignore `numSpeakers`: the models count speakers themselves.
- **Nemotron 3 mode** (`FluidDiarizer+Nemotron.swift`): the `fast128` preset (~200 MB, downloaded into FluidAudio's model cache on first use and loaded offline afterwards). The recording is fed through the streaming API in 60 s pieces rather than `processComplete`, which would hold the mel spectrogram of the whole file (about 180 MB per hour); the output probabilities are identical. The 10 ms frame probabilities go into a `DiarizerTimeline` (0.5 threshold, speech under 0.2 s dropped), so segments and embeddings take the same path as Sortformer mode. `Nemotron3Diarizer` carries stream state and is not thread-safe, so runs on one `FluidDiarizer` go through `nemotronRunGate`; model loads go through the process-wide `nemotronLoadGate`, because FluidAudio deletes a model folder without its version marker and a second first-time load would delete the first one's half-written download. The Nemotron 3 model itself is routed to CPU + Neural Engine, and so is the WeSpeaker embedding pass that follows, as in Sortformer mode: it loads with `FluidOfflineProcessor.computeUnits`, the units the offline pipeline and the live matcher use, rather than FluidAudio's default, which is `.all` outside CI and can route WeSpeaker through MPSGraph, whose abort takes the process down.
- **Dual-track diarization:** App and mic tracks are diarized separately. Speaker IDs are prefixed (`R_` for remote/app, `M_` for mic/local), merged, and assigned via `assignSpeakersDualTrack`. Single-source recordings fall back to diarizing the mix with `assignSpeakers`.
- **Sortformer post-hoc embeddings:** `FluidDiarizer+SortformerEmbeddings.swift` extracts per-speaker WeSpeaker embeddings after Sortformer diarization (DiariZen-style hybrid), using overlap-excluded masks so mixed-speaker frames don't contaminate centroids. Enables `SpeakerMatcher` recognition when using the Sortformer mode, and the Nemotron 3 mode (an 8-speaker Sortformer) reuses it on its own timeline.
- `SpeakerMatcher` stores speakers in `speakers.json` with a running-mean **centroid** (primary anchor) plus a recent-samples FIFO (max 3, fallback when centroid match is borderline). Quality filter: embeddings from segments shorter than `minSpeakingTimeForCentroid` (3 s) are kept as fallback samples but excluded from the centroid. Threshold 0.40, confidence margin 0.10. A speaker first confirmed on a short segment carries `awaitsQualifyingSample` until a qualifying confirmation sets its centroid, so its short samples never seed it, not even through a merge. A legacy entry (written before the centroid existed: no centroid and no marker) is matched against its samples alone until its first confirmation of any length persists their mean as the centroid seed; merging seeds from the legacy side's own samples only. An all-zero persisted centroid counts as absent, and one persisted with a count of 0 weighs as one sample. Known limit: entries an older version created from a short first segment carry no marker and are still treated as legacy.
- **Live speaker matching:** `LiveSpeakerMatcher` (actor) matches finalized live-caption utterances against `speakers.json` in real time using the same WeSpeaker CoreML model as the batch pipeline — voices enrolled post-meeting are recognised in subsequent live sessions without re-enrollment. Cold-start optimisation: caches the WeSpeaker mask frame count in `UserDefaults` so only the embedding model is loaded on subsequent launches.
- **Experimental diarization tuning:** `AppSettings` exposes five `OfflineDiarizerConfig` knobs (`clusterThreshold`, `warmStartFa`, `warmStartFb`, `minSegmentDurationSeconds`, `excludeOverlap`) editable via Settings → Speakers → Experimental: Diarization Tuning. All default to FluidAudio community values; a reset button restores defaults.
- `DiarizationProvider` protocol enables mock injection in tests.
