# Transcription and live captions

ASR engines, WhisperKit model handling, vocabulary, live captions and VAD.

**Rule for every WhisperKit call that can download or load a model:** pass `downloadBase: WhisperKitLocalSnapshot.downloadBase`. Without it the library silently writes into `~/Documents/huggingface`, which iCloud can sync (issue #640). Use `downloadBaseLocation` only for a read that must not create the folder.

**Transcription engines:**
- `TranscribingEngine` protocol abstracts ASR backends. `WhisperKitEngine` supports 99+ languages and `ParakeetEngine` supports 25 European languages. `GigaAMEngine` uses fixed Russian on Apple silicon.
- `AppSettings.transcriptionEngine` enum (`.whisperKit` / `.parakeet` / `.gigaAM`) selects the engine. Settings UI shows engine picker; engine-specific options hidden when not selected. `availableCases` (filtered by `isAvailable`) is the picker source — a capability hook kept for engines with stricter OS floors.
- Parakeet auto-detects language (no parameter). WhisperKit supports explicit language selection.
- **GigaAM v3 E2E-CTC** downloads a pinned [Core ML conversion](https://huggingface.co/inhum/gigaam-v3-coreml), verifies the assets and compiles them into the model cache. It uses windows of up to 25 seconds, with cuts near quiet points, and maps CTC frame offsets back to the recording timeline for speaker diarization. Vocabulary rules still apply after recognition through the shared terminology normalizer. The live caption backend follows the existing language routing.
- **Custom vocabulary** is one shared one-term-per-line file (`AppSettings.customVocabularyPath`, resolved through `VocabularyFileAccess` for sandbox bookmark access) used by both engines, not a Parakeet-only setting. One switch, `AppSettings.customVocabularyEnabled` (Settings → Transcription → Vocabulary, "Use custom vocabulary"; the file row is hidden while it is off, an ⓘ `HelpBadge` beside it explains it on hover, adding the experimental warning while WhisperKit is selected rather than showing captions), decides whether either engine reads it: off, Parakeet gets an empty path from `EngineController` and WhisperKit's `vocabularyPromptEnabled` is false. An upgrade without the key starts it where the engine in use was (`initialCustomVocabularyEnabled`): for WhisperKit the old `whisperKitVocabularyPromptEnabled` flag, for Parakeet whether a file is set. It is derived once, so it only preserves behaviour for that engine: a Parakeet user with a file who later picks WhisperKit gets the experimental prompt on, and a WhisperKit user with the old flag off who later picks Parakeet gets no boosting (an `||` of both would turn the WhisperKit prompt on for everyone with a file). On, Parakeet applies the file via CTC boosting and WhisperKit via `WhisperVocabularyPrompt` turning the file into a bounded decoder-prompt hint, where the 32-token budget keeps the earliest terms (the file row's help says so) — WhisperKit shares its 224-token decoder context between that prompt and generated tokens, and a dense recording can lose whole sentences to it, so Parakeet is the recommended engine for vocabulary boosting.
- **Terminology normalization** (`TerminologyNormalizer`, Settings → Transcription → Vocabulary → Canonical terminology) is a separate, engine-independent post-ASR pass: opt-in `Canonical => spoken variant | another variant` rules, applied to transcript segments after transcription regardless of which engine or vocabulary feature was used. The rules come from the Settings text area or, when one is selected, from an optional rules file (`AppSettings+TerminologyRules`, bookmarked like the vocabulary file, same syntax and limits). The file is read afresh in the per-job snapshot (`terminologyNormalizerForJob`), so an edit reaches the next job without a relaunch and never half of a running one; while a file is set the text area shows its contents read-only, as of the last read. A file that cannot be read, is not a regular file, is not UTF-8 or exceeds 64 KiB applies no rules, logs it and shows it in the Settings status: it never falls back to the text area, whose rules would then be applied without anyone being able to tell why.
- **An already-fetched WhisperKit model loads without the Hub.** `loadModel()` asks `WhisperKitLocalSnapshot` first and only downloads when nothing usable is there, because `WhisperKit.download` reaches huggingface.co before it inspects any local file (issue #736). That type carries the full mechanism and the condition under which it can be deleted again. The guarantee has a bound: the locator checks the CoreML bundles, not the tokenizer, which WhisperKit loads from a separate `models/openai/whisper-*` folder and otherwise fetches from the Hub, so a model folder copied in by hand without that cache still fails offline. Two consequences: a complete but stale copy is no longer revalidated on each load, and the normal online path no longer makes a Hub round trip per model file.
- **WhisperKit models live in `~/Library/Application Support/MeetingTranscriber/huggingface`, not the library default `~/Documents/huggingface`** (issue #640): Documents is synced by iCloud "Desktop & Documents", which uploaded every ~1 GB variant. `WhisperKitLocalSnapshot.downloadBaseLocation` is the single source of truth (`downloadBase` is the same path, created and excluded from Time Machine on first access, and is what writers use); it is passed to the download, to the locator (`HubApiWrapper(downloadBase:)`) and to `WhisperKitConfig`, where it also sets the tokenizer cache (`tokenizerFolder ?? downloadBase`); any new WhisperKit call must pass it too or it silently writes into Documents again. Not `Caches`, because a purge there would mean a silent gigabyte download or a failed load offline; the folder is excluded from Time Machine instead. `WhisperKitModelMigration` moves a complete, non-evicted copy of the variant being loaded (with its Hub download metadata under `.cache/huggingface/download/<variant>`) out of Documents on the next load, once per variant and process, on a background task the engine awaits through `WhisperKitModelSource.prepare` before its lookup, so `locateLocal` stays a pure path check. It copies the small `openai/whisper-*` tokenizers (staged under a temporary name, then renamed into place), never the whole shared `huggingface` folder, which other swift-transformers tools also use; anything it cannot move is downloaded afresh. Consequence worth knowing: the test suite goes through the production locator too, so `swift test` on a developer machine migrates that machine's models, and an older installed build will then download its model into Documents again. To keep a run off the real folders, give it another home: `CFFIXED_USER_HOME=<dir> swift test` resolves Application Support, Documents and Caches inside `<dir>`. Leave `HOME` alone: the Security framework finds the default keychain through it, and with `HOME` moved every keychain test fails. UserDefaults, keychains and TCC grants are per user and stay put, and an ffmpeg in `~/.local/bin` is no longer found unless linked in. The self-hosted CI test steps run that way, in a per-runner home from `.github/actions/runner-home`, which makes that link, because the Mini's runners share one account with each other and with the dev app; `RunnerHomeIsolationTests` fails a self-hosted run that does not.
- **Custom WhisperKit model** (Settings → Transcription → Model → "Custom model…"): another Hugging Face repository plus variant folder, or a model folder on disk. `AppSettings.whisperKitModelSelection` resolves it into a variant plus `WhisperKitModelOrigin` (`.hub(repoID:)` / `.localFolder`), and the engine treats the origin as part of the model's identity, because a fine-tune usually keeps its base model's folder name. `whisperKitModel` always stays a stock variant, and an unfinished custom model resolves to it. The Settings fields are `DraftTextField`s that write on Return or when the field is left (focus loss, or the field going away), not per keystroke, because the engine observer acts on every settings write; "Load Model" hands over a pending edit before it reads the selection, and so does closing the Settings window, which only hides it, so neither focus loss nor the field going away happens there (`WhisperKitCustomModelDrafts.settingsWindowWillClose`, only for the window with the Settings scene id and only while WhisperKit is selected and the custom model is on). Each field commits on its own, so changing the repository and then the variant is two commits, and in between the new repository is paired with the old variant. A value that is written is used as entered, so a wrong one fails the load with its reason rather than quietly running another model. A Hub origin reuses the local-first path above with its own repo root, and the download is accepted only when the returned folder is named exactly like the variant (`WhisperKitModelSource.downloadExactly`): WhisperKit matches `*<variant>/*`, so a tail-of-the-name variant would load once and never offline. A picked folder is never downloaded, so `WhisperKitLocalSnapshot.checkModelFolder` also requires the tokenizer files there, so that the folder is self-sufficient; no `tokenizerFolder` is passed, so WhisperKit uses the app's `downloadBase` in its place and looks in the app's tokenizer cache (`<downloadBase>/models/openai/whisper-<detected size>`) first, then at the top of `downloadBase`, then in the folder (and its own `models/openai/whisper-<size>`), and fetches from the Hub into that cache last. The folder goes through a security-scoped bookmark like the vocabulary file (fail-fast resolve for the validation line, full resolve for the load, stale repair at launch). A failed load keeps a path-free `WhisperKitEngine.loadFailureReason` (`WhisperKitLoadFailureReason`) that Settings shows under the status and `TranscriptionError.modelNotLoaded(reason:)` carries into the job error.
- `EngineController` (`@MainActor`) owns the engine instances, active-engine selection (`activeTranscriptionEngine`, used by `PipelineQueue`), settings → engine language/vocabulary sync (up-front + reactive), and model lifetime. `AppState` exposes it as `engines`; launch preload runs only when idle unloading is off; with it on, launch only downloads a missing model.
- **ASR model retention** is controlled by `AppSettings.unloadModelsWhenIdle` (Settings → Transcription → "Unload models when idle", default on). It decides only what stays in memory; at launch the active engine's model is downloaded when it is not on disk in either state. On, a launch with a local copy does no load and no network work. Without one, `downloadModelIfMissing()` (WhisperKit: no complete local snapshot of a Hub model; Parakeet: `AsrModels.modelsExist` false) fetches the files through the serial `ModelWarmupQueue` and leaves the engine `unloaded`. After a WhisperKit download that fetched something, `EngineController` loads the model once in the same warm-up slot and releases it again if the app is still idle: WhisperKit fetches its tokenizer only during a load, so without that load a fresh install that is offline at its first job could not load the model it had downloaded. That costs one CoreML compile per fresh install or new variant, never on a launch with the model on disk. The download runs as the engine's `modelLoad` flight, so a job that needs the model meanwhile joins it rather than starting a second download, then loads from disk (its attempt carries a generation no caller has, which sends joiners into another pass). When the WhisperKit download fails, joiners get that failure as their own, so a job fails with the reason instead of downloading again. A failed launch download shows as a failed preload does: WhisperKit keeps its `loadFailureReason` under the status, Parakeet only logs. A release during the launch download leaves it alone, since there is no model in memory to drop: the status stays `downloading` with its progress, and a failure still shows its reason; a caller that had joined the download before the release still gives up its own load. A load released during its own download skips the CoreML init. Jobs load the selected engine on demand, and a fully drained pipeline releases the idle WhisperKit/Parakeet model and the queue's cached batch VAD; adjacent queued jobs share the loaded model. A manual "Load Model" remains loaded until that drain. A release keeps WhisperKit's `loadFailureReason`, so a job that failed to load still shows why after the drain; a new load attempt or a model change clears it. Off preserves launch preload and retention exactly: no drain release and no release of the inactive engine after a switch, because `PipelineQueue` holds its engine and keeps running on the old one until the queue is rebuilt. Changing the setting while idle applies immediately; during recording or queued/running work it takes effect at the next safe drain. With it on, switching engines releases the inactive engine once no recording or queue work is using it. Captions that run on the shared engine keep that model resident: `LiveTranscriptionCoordinator.captionsUseEngine` is set when a re-transcribe controller is created, before its `prepare()` loads the engine, and by the controller's `willLoadEngine` callback before the fallback after a failed EOU/Nemotron load does, so a drain release cannot land during either load; after `prepare()` it says whether the controller built re-transcribe pipelines, which covers auto-detect and the fallback after a failed EOU/Nemotron load, and replacing or dropping the controller clears it; the EOU/Nemotron sessions use their own models and are not part of this retention setting. Only in-memory ASR/VAD instances are released: downloaded model files remain in their caches. An unloaded engine still reports `"unloaded"` on `/state`; Settings says "Loads when needed" when idle unloading is enabled.
- **Releasing during a load invalidates that load.** WhisperKit tags `LoadAttempt` with a generation; Parakeet's `SingleFlight<Int>` returns its generation. A release advances the generation and drops the engine's model references. A caller waiting on the released generation returns without restoring that model, while a fresh caller that joined a stale in-flight load retries against the current generation. The lazy transcription load path therefore remains safe when a drain or engine switch overlaps a load. This exception to the usual load postcondition is intentional: after a release, the old caller may finish with no model loaded.

**Live captions (PoC):** "Enable live transcription during recording" in Settings → Transcription (`AppSettings.liveTranscriptionEnabled`, off by default; enabling downloads a ~0.6 GB model on first use behind a consent alert). Nested "Show caption overlay" (`AppSettings.liveCaptionsOverlayEnabled`, default on) hides `LiveCaptionsOverlay` without stopping the pipeline; `LiveCaptionsState` and `/state.liveCaptions` keep updating.
- A finalized line sets a reading hold of 0.3 seconds per word, with a 4-second minimum and an 6-second maximum. The maximum is 20 words at that rate, about what two lines show, so a final longer than its row is not held for words already clipped off it: before streaming finals were split into lines (below), a 104-word Parakeet EOU final kept the bar up for 31 seconds after the speech stopped. EOU and Nemotron finals are now at most 14 words, a 4.2-second hold, so the maximum only binds for re-transcribe finals. The 2-second fade starts only after that hold, and while a hypothesis is showing, not before it has gone 5 seconds without an update; content, hypotheses included, clears when the fade completes. The 5-second limit exists because no backend guarantees a final after a partial: `StreamingTranscriber` and the Nemotron session send nothing when the final decode is empty or throws, and the EOU session sends nothing when the final adds no text, so a hypothesis can be left standing until the next recording. The limit sits above the slowest partial cadence: Nemotron decodes every ~2.24 seconds and skips unchanged text, so two unchanged decodes leave 4.48 seconds between partials. A new partial or final restores full opacity; a final sets a fresh reading deadline. `LiveCaptionsState` exposes the fade target and schedules it with a cancellable task; the overlay animates opacity without periodically rebuilding caption text. The overlay joins consecutive finals of one channel and speaker into one row, and the hypothesis continues the bottom row under that row's name when that row is on its channel (it has no match yet; under the channel label it stood in a row of its own below every named row, and when the next line turns out to be another speaker, those words move to their own row once matched), so the split lines of one speaker read as one text and the label shows once per speaker turn; a row per line showed fragments such as "if the" with the label repeated on every row. `LiveCaptionsState` keeps up to six finals and, past that, drops all but the newest two at once: dropping the oldest line on each new line re-wraps the joined row every time, while dropping the earlier lines at once re-wraps it once per five lines. The second line is kept so the newest has a line before it to join and to take its speaker from (`inheritSpeaker`, `resolveUnmatched`); dropping down to one line left every sixth line of a monologue under the channel label. Rows are keyed by position, so a row that grows or is relabelled keeps its view. Once a new turn starts (the newest final has another channel or speaker than the lines before it), those earlier lines leave after `earlierTurnHold` (4 s); before, they stayed until the page turn, and on a two-speaker recording a guest's row stood 18 s above the interviewer's. A relabel that joins a line to the running turn moves the boundary back, so the expiry keeps it. Each row shows its complete text, capped at exactly two line heights of the row font, from its `NSFont` metrics, and clipped at the top, so a long row shows its newest words and cannot push the other channel's row out of the bar; a one-line row keeps its own height. The text is not trimmed to a word budget: dropping the oldest word on each partial re-wrapped both lines and moved every word, so the newest word had no fixed place. Untrimmed, the line breaks hold still, new words land at the end of the bottom line, and a full line leaves at the top. Hypothesis text is not cross-faded, because a cross-fade showed the old and new text overlaid: the `Text` uses `.contentTransition(.identity)`, so new words swap in at once, and only its position eases (0.2 s), so a full line slides out through the top of the clip instead of jumping. A single `Text` cannot fade one of its lines, and a fade band at the top edge would leave a faint copy of the hidden line on screen. A new row still fades in; a growing row does not. A cap with slack above two lines shows the descenders of the hidden line as a strip. The speaker label sits next to the top visible line. The whole caption box sits in a bottom-aligned viewport in the fixed-size panel, so overflow leaves at the top.
- `LiveCaptionLanguages` owns Nemotron's 39 trained languages, taken from the tokenizer's language tags, and the bare-code aliases `en` → `en-US`, `es` → `es-ES`, `pt` → `pt-BR`, `zh` → `zh-CN`, and `no` → `nb`. The aliases decide coverage only, not the prompt. The tokenizer's tags are all region-qualified (`<de-DE>`, `<ja-JP>`); the set keeps the region only where the tokenizer has more than one dialect, because the pickers produce bare codes, so a hand-set `ja-JP` is not recognised and uses re-transcribe. Lookup normalizes case and underscores. `LiveCaptionsGate.strategy(liveEnabled:engineLanguage:engineSupportsLive:)` is the pure decision function shared by `AppState`, `LiveTranscriptionCoordinator`, `LiveTranscriptionController`, and the Settings footnote and download-consent alert: disabled → off; English → `EouStreamingCaptionSession` (FluidAudio Parakeet EOU); a trained non-English language → `NemotronStreamingCaptionSession`/`NemotronAsrManager` (FluidAudio Nemotron multilingual); auto-detect or any other explicit language → re-transcribe via `StreamingTranscriber` when the engine supports it, else off. With WhisperKit active, auto-detect first detects the language of each recording (below) and may stream through EOU instead. Of the picker languages, `id`, `ms`, `fa`, `fil`, `mk`, `yue` (WhisperKit) and `bs`, `be`, `sr` (Parakeet) are untrained and use re-transcribe; Nemotron's `auto` prompt produced unusable Indonesian (issue #928) and was not measured for the others. Overlay visibility is a separate UI AND (`overlayVisible`); it is not a strategy input.
- `NemotronAsrManager.resolvedLanguageCode` picks the key it hands to FluidAudio from the loaded model's `promptDictionary`, because FluidAudio's own lookup never adds a region and falls back to the `auto` prompt (`ja`, `zh`, `th`, `vi` and `he` have no bare key). Order: the configured code as an exact key when its prompt id is one a trained language uses, then the trained tag's key, then the tag with its likely region (`ja` → `ja-JP`). The first step keeps the model's own dialect for bare codes: `es` sends prompt 3, shared with `es-US`, and `pt` sends prompt 13, shared with `pt-PT`, as before this lookup existed; the model's bare `no` key (`no-NO`, 27) has no tokenizer tag, so `no` sends `nb`. A prompt key such as `id-ID` does not make Indonesian supported. With the shipped models every trained language resolves; if one did not, the manager logs the code and throws after the model load, and the controller's load-failure fallback takes over. `Tests/Fixtures/nemotron_prompt_metadata.json` is the shipped dictionary and tokenizer tags (identical for the latin and multilingual 2240 ms variants), and one table test pins strategy and prompt key for every picker language.
- In auto-detect with WhisperKit active and a multilingual model loaded (`supportsCaptionLanguageDetection`; an English-only model cannot detect and re-transcribes as before, and the engine remembers a released model's kind so Settings keeps describing it while unloaded), a recording holds caption audio (up to 60 s) and shows `Detecting language…`, and `/state.liveCaptions.detectingLanguage` is true, instead of running caption decodes. The probe is also armed at idle, holding nothing, and reads false there. Per-channel FluidVAD probes (`CaptionLanguageProbe`) collect four seconds of speech; the first channel to get there supplies one window to the engine's `detectLanguage(samples:)`, which loads the model on demand and asks WhisperKit for the language probabilities. A window decides at a probability of at least 0.8 (`CaptionLanguageProbeDecision`). English needs two consecutive confident windows, because one English window can be a greeting or a shared clip in a meeting held in another language; a confident other language decides at once, and an unsure window breaks the English run and collects the next four seconds on either channel, up to four windows. English streams through both Parakeet EOU sessions, with the held audio replayed in order, so no speech is lost. Everything else re-transcribes with no language set, so WhisperKit still detects the language per decode and a meeting that changes language is not decoded in its first one; only the newest 8 s of the hold are replayed, which keeps the sentence before the decision without a backlog the length of the detection wait on a path that decodes at about real time. A thrown or unsupported detection, or four unsure windows, take the same route. The decision lasts one recording: a meeting that turns English after the detection stays on re-transcribe, and one that leaves English stays on EOU, which writes the new language as English-sounding fragments until the next recording. This is a known limit: on an English clip that switched to German at about 57 s, EOU captioned the English correctly and the German as scattered pieces such as "come and good on" and "comet". Re-detecting during EOU would add a WhisperKit detection every few seconds to every English meeting. The EOU models load once per controller, on the first English decision, and are kept for later recordings; a failed load is logged and not retried until the controller is rebuilt, and `warmup` stays `ready` because re-transcribe still captions. Neither a stop nor the next recording's start waits for a detection or an EOU load in flight: stopping keeps it from installing, and the next recording's generation drops its result. A recording that stops before the decision gets no captions. The controller logs one decision per recording with language, probability, attempt and elapsed time, never transcript text. The WhisperKit model stays held for captions (`usesTranscriptionEngine`) even after English is chosen, since the next recording probes again. Nemotron for other detected languages is not used: it would have to stay resident next to WhisperKit, which does not fit 8 GB. The thresholds (0.8, four seconds, two English windows, four attempts, 60 s hold, 8 s replay) were not swept; they come from one 8 GB M3 Mac (macOS 27.3) and one English source. There, over the same 90 s of an English video in three paired runs with single-window detection, EOU showed the same phrases 3 to 17 s sooner than auto-detect re-transcription and dropped at most 0.1 s of audio, where re-transcription dropped 11.3 to 20.8 s; detection decided after 13 to 21 s. Explicit-language routing and the Parakeet engine are unchanged.
- Both streaming backends are engine-independent (drive their own FluidAudio models directly), so captions work even when the active `TranscribingEngine` has no live re-transcribe hook. `LiveTranscriptionController` wires the resolved per-channel pipeline to both `DualSourceRecorder` sinks and feeds `LiveCaptionsState`, which backs the `LiveCaptionsOverlay` window. A final is shown immediately; asynchronous speaker matching updates that still-retained final and any short lines inheriting from it, without clearing a newer hypothesis or restarting its reading hold. Until its match lands (0.1–0.25 s, measured at 5 Hz on a live recording), the final, and any short line inheriting from it, continues the row before it on its channel and starts no turn, like the hypothesis: shown under the channel label meanwhile, it split the row and joined it again, so the bar flashed between a name and "Remote" on at least 15 of 74 lines. A relabel that gives a line another speaker than its neighbours moves it into a row of its own. A final with no confident match keeps the speaker of the line before it when that speaker is also its nearest enrolled voice (`resolveUnmatched`), and keeps the channel label otherwise, since it may be a new voice. A voice counts as nearest only within `LiveSpeakerMatch.nearestSlack` (0.05) of the match threshold (0.40): unbounded, with one voice enrolled, an unenrolled guest answering that speaker took their name on every line until the turn changed channel. The 0.05 was not measured on live slices; in the batch recognition log of one machine, 5 % of the distances to the second-nearest (another) voice were under 0.42 and 10 % under 0.48. In a replay of a four-voice podcast, 7 of 9 unmatched lines sat inside one speaker's turn with that speaker nearest, and would otherwise have split it as A / Remote / A; in a two-speaker replay, the host's three unmatched lines after the guest had the host nearest and stayed "Remote" instead of taking the guest's name. A final with less than one second of audio (`minSpeakerMatchSamples`) is not matched, because the embedding extractor loops short audio up to its window, and whether such an embedding passes the match threshold was not measured. It takes the speaker of the line before it on the same channel instead (`inheritSpeaker`), also when that line's match lands later: such a line is almost always the end of a sentence the split cut off. In a replay of four minutes of a two-speaker podcast through the EOU session, 8 of 65 lines were under one second ("etc", "terraform", "problem which was"), all of them the end of the previous speaker's sentence. The cost: a sub-second line that is in fact a new speaker's first words ("yeah") shows the previous speaker's name. `ModelWarmupQueue` serializes model warm-up loads so the ASR engine and streaming models don't compile/load concurrently at launch.
- `LiveTranscriptionCoordinator.warmup` (`LiveCaptionsWarmup`) is the state of the current controller's model warm-up: `idle` without a controller (`"none"` on `/state`), `preparing` from the moment the controller is built (time spent waiting in `ModelWarmupQueue` included) until its `prepare()` returns, then `ready` or `failed` with the load error. It is `failed` only when no caption model loaded: a failed Nemotron/EOU load with no streaming engine to fall back to, or a re-transcribe path (selected or fallback) whose engine is not `loaded` after `loadModel()`, which does not throw. In that second case the pipelines are still built, so each utterance retries the load through the engine, and `warmup` stays `failed` even when such a retry succeeds, until the controller is rebuilt. On the re-transcribe strategy a recording that starts before `prepare()` reaches the pipelines builds them in `prepareForNextRecording()`; `prepare()` then still loads the engine when it is not `loaded`, so the state always follows a load attempt (and a loaded model is not rebuilt). A fallback to re-transcribe with a loaded engine and a failed speaker-matcher load are `ready`. The failure text has the home directory shortened to `~` (`AppPaths.abbreviatingHome`, the rule `/ui/tree` uses), since a CoreML error can carry a model path. Settings → Transcription shows it under the live-captions toggle, with a spinner and the elapsed time while it is `preparing` and, when `failed`, the hint to turn live captions off and on, since a failed load is retried only when a caption setting rebuilds the controller; the menu-bar dropdown shows "Preparing live captions…" while it is `preparing`, and `/state.liveCaptions` carries it as `warmup` and `warmupFailure`. The coordinator logs each warm-up's start and its outcome with the seconds it took (category `LiveTranscription`, not gated on verbose diagnostics: the lines carry the language code and no speech), counted from the build like the Settings timer. A load compiles the model for the Neural Engine in a system process (`ANECompilerService`), and not only on first use; the app has no progress figure for it, which is why the Settings line says it can take a minute or more. Measured on an 8 GB M3 Mac, macOS 27.3: a first Swedish (Nemotron) warm-up took 59.9 s with the compiler active for 49 s of it, and a WhisperKit large-v3-turbo reload after an idle unload took 54.8 s with the compiler active for 10 s; three others took 1.7 to 3.6 s with the compiler idle in the two that were checked. A longer one was not observed.
- Dropping a controller (a toggle, engine or language change while idle, or the deferred rebuild at the idle `flush()`) calls its `cancelPrepare()`. Both warm-ups go through the serial `ModelWarmupQueue`, so a stale one never ran beside its successor, it delayed it: the cancel skips a `prepare()` still waiting in the queue and the steps after a load that is already running. `prepare()` checks the flag between its steps: before the speaker matcher, before the pipelines, between the two EOU channels, before the engine load of the re-transcribe fallback, after the pipelines are built, and after the engine load `prepare()` runs itself when a recording built the re-transcribe pipelines first; the last two come before it binds feeds and publishes its backend. A load that is already running is not interrupted, and it is a flag rather than task cancellation so a shared engine load or a model download is never aborted halfway. While recording nothing is dropped or cancelled, as before, and an `attachSinks` in flight counts as recording: a manual start builds its recorder before the state is recording, and a controller dropped in that window would be cancelled while the new recording is attached to it, so the change waits for the next idle `flush()`. If that manual start then throws, the phase never becomes recording and no flush follows, so the old controller stays until the next recording stops or another caption setting changes. A change deferred this way leaves `warmup` as it was until then, so with captions turned off during a recording the menu and `/state` still report the kept controller's state, and the retry hint takes effect only after the recording stops.
- EOU and Nemotron use `StreamingCaptionSplitter` to commit text-only lines at 14 complete words, keeping the next growing token in the hypothesis until a word boundary is known. EOU also commits an unchanged hypothesis after 0.7 seconds of ingested audio; the session checks this on every buffer, including buffers with no new ASR callback. The EOU manager's transcript is cumulative, so the splitter tracks a character offset and rebases it at a real EOU; reset and audio discontinuity clear the offset. Nemotron keeps its existing VAD speech-end and five-second force-flush boundaries and does not use unchanged text as a pause signal, because its decoder updates about every 2.24 seconds: its splitter is built with an infinite pause. Text splits do not finish or reset either model. The session seams expose no word-level audio timestamps, so a synthetic line receives the available unassigned audio once. A line closed by the pause rule gets the audio up to the last transcript change, so its slice does not include the pause, and the next line starts after it. A line with no audio left (further lines from that same update, a remainder finalized by an EOU whose timestamp lies before the last split, and a remainder left by a 14-word split and closed by the pause rule with no text change in between, whose slice runs from the cursor to the last text change, the same moment) takes the previous line's speaker like any line under one second. The pause rule commits the hypothesis as it stands, without holding back the last token: when the model later extends that token without a space, the extension starts the next line. On `two_speakers_en.wav` the model's own "featurement" (one final before the split) became "feature" and "ment" on two lines.
- `StreamingTranscriber` and `NemotronStreamingCaptionSession` make up to three VAD attempts per chunk (`vadAttemptsPerChunk`), then log and move on so a persistent VAD error cannot grow the backlog. `StreamingTranscriber` drops that chunk; Nemotron has already fed it to its cache-aware ASR stream and treats it as no boundary, so the stream is never spliced.
- Each channel feed retains up to 10 seconds of queued audio by duration (the `LiveTranscriptionController` default). The consumer awaits each ingest, so the queue fills for as long as one decode runs: the bound must exceed the slowest single decode plus the 0.8-second partial gate, or every such decode overflows and the reset discards the utterance it was decoding. On an 8 GB Mac with large-v3-turbo the slowest decode per run ranged from 5.8 to 15.5 s, so 10 s does not meet that rule there: it trades lag against loss, and holds up because overflow drops only the excess. Overflow drops oldest whole buffers until the queue fits again; the consumer resets the pipeline and app resampler before the next retained buffer so speech is never joined across a gap. Dropping only the excess, not the whole backlog, matters under sustained slower-than-real-time decoding: on that Mac, skipping to the newest buffer lost the full 10 s at every overflow, and in three of four paired runs over the same clip it lost 20 to 50 s where dropping oldest lost 1 to 5 s, at similar median lag (in the fourth, a 51 s decode stall made dropping oldest lose 62 s of the 130.7 s clip, about 47 %). Queue-dropped audio never reaches the pipeline; with Verbose Diagnostic Logging the stop-time flush logs each channel's dropped seconds and gap count. The bound is injectable; `LiveTranscriptionE2ETests` uses 60 seconds because it delivers its fixture much faster than real time. While the language is detected, a held feed has no consumer and keeps up to 60 seconds; a longer cold start drops the oldest audio in one discontinuity. After English is chosen it replays that run and returns to the normal bound once it has caught up. Retiring a feed at stop drains the retained pre-stop buffers before the pipeline final flush. For active re-transcribed speech, that flush sends any incomplete VAD chunk to the final decode, and the usual one-second noise cutoff applies there too. The auto-detect re-transcribe path skips partials while queued and unprocessed audio exceeds the 0.8-second partial interval, so a machine that decodes slower than real time spends its decode time on finals; speech-end, five-second and recording-stop finals still run. EOU and Nemotron ignore the partial backlog hint but reset their stream state after a gap; a stall longer than the bound there loses the oldest audio instead of lagging.
- The caption panel moves on Option-drag from screen-coordinate mouse deltas; each proposed frame is clamped inside the visible frame of its owning screen. The move observer saves only while the left button is down, including after Option is released mid-drag, and stops at mouse-up. A dragged event handled with the button already up (queued behind a main-thread stall) is dropped, so the panel never stands where nothing was saved. macOS 27.2 relocates a panel dropped with the pointer on a screen edge, 2 to 190 ms after mouse-up (likely window tiling; not reproduced on 27.3 with a physical mouse or synthetic events); a move by the system within `dropRelocationWindow` (0.5 s) of a drag's mouse-up is undone by putting the panel back where it was dropped. The drop is the origin the drag last set, not the frame at mouse-up, which the system may already have moved; the mouse-up then puts the panel back at once.

**VAD preprocessing:**
- `FluidVAD` wraps FluidAudio Silero v6 for voice activity detection. When enabled (`AppSettings.vadEnabled`), silence is trimmed before transcription and timestamps are remapped back to the original timeline via `VadSegmentMap`.
- `PipelineQueue` holds a cached `FluidVAD` instance (reused across jobs). Pass `vadConfig: nil` to disable.
