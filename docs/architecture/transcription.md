# Transcription and live captions

ASR engines, WhisperKit model handling, vocabulary, live captions and VAD.

**Rule for every WhisperKit call that can download or load a model:** pass `downloadBase: WhisperKitLocalSnapshot.downloadBase`. Without it the library silently writes into `~/Documents/huggingface`, which iCloud can sync (issue #640). Use `downloadBaseLocation` only for a read that must not create the folder.

**Transcription engines:**
- `TranscribingEngine` protocol abstracts ASR backends. Two implementations: `WhisperKitEngine` (99+ languages, ~1 GB model) and `ParakeetEngine` (25 EU languages, ~50 MB model, ~10× faster).
- `AppSettings.transcriptionEngine` enum (`.whisperKit` / `.parakeet`) selects the engine. Settings UI shows engine picker; engine-specific options hidden when not selected. `availableCases` (filtered by `isAvailable`) is the picker source — a capability hook kept for engines with stricter OS floors.
- Parakeet auto-detects language (no parameter). WhisperKit supports explicit language selection.
- **Custom vocabulary** is one shared one-term-per-line file (`AppSettings.customVocabularyPath`, resolved through `VocabularyFileAccess` for sandbox bookmark access) used by both engines, not a Parakeet-only setting: Parakeet applies it via CTC boosting; WhisperKit applies it only when `AppSettings.whisperKitVocabularyPromptEnabled` (off by default, Settings → Transcribe, "experimental") is on, via `WhisperVocabularyPrompt` turning the file into a bounded decoder-prompt hint — WhisperKit shares its 224-token decoder context between that prompt and generated tokens, and a dense recording can lose whole sentences to it, so Parakeet is the recommended engine for vocabulary boosting.
- **Terminology normalization** (`TerminologyNormalizer`, Settings → Transcribe → Terminology Rules) is a separate, engine-independent post-ASR pass: opt-in `Canonical => spoken variant | another variant` rules, applied to transcript segments after transcription regardless of which engine or vocabulary feature was used. The rules come from the Settings text area or, when one is selected, from an optional rules file (`AppSettings+TerminologyRules`, bookmarked like the vocabulary file, same syntax and limits). The file is read afresh in the per-job snapshot (`terminologyNormalizerForJob`), so an edit reaches the next job without a relaunch and never half of a running one; while a file is set the text area shows its contents read-only. A file that cannot be read, is not UTF-8 or exceeds 64 KiB applies no rules, logs it and shows it in the Settings status: it never falls back to the text area, whose rules would then be applied without anyone being able to tell why.
- **An already-fetched WhisperKit model loads without the Hub.** `loadModel()` asks `WhisperKitLocalSnapshot` first and only downloads when nothing usable is there, because `WhisperKit.download` reaches huggingface.co before it inspects any local file (issue #736). That type carries the full mechanism and the condition under which it can be deleted again. The guarantee has a bound: the locator checks the CoreML bundles, not the tokenizer, which WhisperKit loads from a separate `models/openai/whisper-*` folder and otherwise fetches from the Hub, so a model folder copied in by hand without that cache still fails offline. Two consequences: a complete but stale copy is no longer revalidated on each load, and the normal online path no longer makes a Hub round trip per model file.
- **WhisperKit models live in `~/Library/Application Support/MeetingTranscriber/huggingface`, not the library default `~/Documents/huggingface`** (issue #640): Documents is synced by iCloud "Desktop & Documents", which uploaded every ~1 GB variant. `WhisperKitLocalSnapshot.downloadBaseLocation` is the single source of truth (`downloadBase` is the same path, created and excluded from Time Machine on first access, and is what writers use); it is passed to the download, to the locator (`HubApiWrapper(downloadBase:)`) and to `WhisperKitConfig`, where it also sets the tokenizer cache (`tokenizerFolder ?? downloadBase`); any new WhisperKit call must pass it too or it silently writes into Documents again. Not `Caches`, because a purge there would mean a silent gigabyte download or a failed load offline; the folder is excluded from Time Machine instead. `WhisperKitModelMigration` moves a complete, non-evicted copy of the variant being loaded (with its Hub download metadata under `.cache/huggingface/download/<variant>`) out of Documents on the next load, once per variant and process, on a background task the engine awaits through `WhisperKitModelSource.prepare` before its lookup, so `locateLocal` stays a pure path check. It copies the small `openai/whisper-*` tokenizers (staged under a temporary name, then renamed into place), never the whole shared `huggingface` folder, which other swift-transformers tools also use; anything it cannot move is downloaded afresh. Consequence worth knowing: the test suite goes through the production locator too, so `swift test` on a developer machine migrates that machine's models, and an older installed build will then download its model into Documents again. To keep a run off the real folders, give it another home: `CFFIXED_USER_HOME=<dir> swift test` resolves Application Support, Documents and Caches inside `<dir>`. Leave `HOME` alone: the Security framework finds the default keychain through it, and with `HOME` moved every keychain test fails. UserDefaults, keychains and TCC grants are per user and stay put, and an ffmpeg in `~/.local/bin` is no longer found unless linked in. The self-hosted CI test steps run that way, in a per-runner home from `.github/actions/runner-home`, which makes that link, because the Mini's runners share one account with each other and with the dev app; `RunnerHomeIsolationTests` fails a self-hosted run that does not.
- **Custom WhisperKit model** (Settings → Transcribe → Model → "Custom model…"): another Hugging Face repository plus variant folder, or a model folder on disk. `AppSettings.whisperKitModelSelection` resolves it into a variant plus `WhisperKitModelOrigin` (`.hub(repoID:)` / `.localFolder`), and the engine treats the origin as part of the model's identity, because a fine-tune usually keeps its base model's folder name. `whisperKitModel` always stays a stock variant, and an unfinished custom model resolves to it. The Settings fields are `DraftTextField`s that write on Return or when the field is left (focus loss, or the field going away), not per keystroke, because the engine observer acts on every settings write; "Load Model" hands over a pending edit before it reads the selection, and so does closing the Settings window, which only hides it, so neither focus loss nor the field going away happens there (`WhisperKitCustomModelDrafts.settingsWindowWillClose`, only for the window with the Settings scene id and only while WhisperKit is selected and the custom model is on). Each field commits on its own, so changing the repository and then the variant is two commits, and in between the new repository is paired with the old variant. A value that is written is used as entered, so a wrong one fails the load with its reason rather than quietly running another model. A Hub origin reuses the local-first path above with its own repo root, and the download is accepted only when the returned folder is named exactly like the variant (`WhisperKitModelSource.downloadExactly`): WhisperKit matches `*<variant>/*`, so a tail-of-the-name variant would load once and never offline. A picked folder is never downloaded, so `WhisperKitLocalSnapshot.checkModelFolder` also requires the tokenizer files there, so that the folder is self-sufficient; no `tokenizerFolder` is passed, so WhisperKit uses the app's `downloadBase` in its place and looks in the app's tokenizer cache (`<downloadBase>/models/openai/whisper-<detected size>`) first, then at the top of `downloadBase`, then in the folder (and its own `models/openai/whisper-<size>`), and fetches from the Hub into that cache last. The folder goes through a security-scoped bookmark like the vocabulary file (fail-fast resolve for the validation line, full resolve for the load, stale repair at launch). A failed load keeps a path-free `WhisperKitEngine.loadFailureReason` (`WhisperKitLoadFailureReason`) that Settings shows under the status and `TranscriptionError.modelNotLoaded(reason:)` carries into the job error.
- `EngineController` (`@MainActor`) owns the engine instances + the active-engine selection (`activeTranscriptionEngine`, used by `PipelineQueue`) + the settings → engine language/vocabulary sync (up-front + reactive) + launch model preload. `AppState` exposes it as `engines`.

**Live captions (PoC):** "Enable live transcription during recording" in Settings → Transcribe (`AppSettings.liveTranscriptionEnabled`, off by default; enabling downloads a ~0.6 GB model on first use behind a consent alert). Nested "Show caption overlay" (`AppSettings.liveCaptionsOverlayEnabled`, default on) hides `LiveCaptionsOverlay` without stopping the pipeline; `LiveCaptionsState` and `/state.liveCaptions` keep updating.
- `LiveCaptionsGate.strategy(liveEnabled:engineLanguage:engineSupportsLive:)` is the pure decision function (shared by `AppState`, `LiveTranscriptionCoordinator`, `LiveTranscriptionController`) that routes each channel by the active engine's **explicitly configured** language: `en` → `EouStreamingCaptionSession` (FluidAudio Parakeet EOU), any other explicit language → `NemotronStreamingCaptionSession`/`NemotronAsrManager` (FluidAudio Nemotron multilingual), auto-detect → re-transcribe via `StreamingTranscriber` if the engine supports it, else off. Overlay visibility is a separate UI AND (`overlayVisible`); it is not a strategy input.
- Both streaming backends are engine-independent (drive their own FluidAudio models directly), so captions work even when the active `TranscribingEngine` has no live re-transcribe hook. `LiveTranscriptionController` wires the resolved per-channel pipeline to both `DualSourceRecorder` sinks and feeds `LiveCaptionsState`, which backs the `LiveCaptionsOverlay` window. `ModelWarmupQueue` serializes model warm-up loads so the ASR engine and streaming models don't compile/load concurrently at launch.

**VAD preprocessing:**
- `FluidVAD` wraps FluidAudio Silero v6 for voice activity detection. When enabled (`AppSettings.vadEnabled`), silence is trimmed before transcription and timestamps are remapped back to the original timeline via `VadSegmentMap`.
- `PipelineQueue` holds a cached `FluidVAD` instance (reused across jobs). Pass `vadConfig: nil` to disable.
